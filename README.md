**Codespaces Chromium**

このワークスペースは、別のコンテナでChromiumデスクトップを実行し、そのWebインターフェースをプライベートなCodespacesポート経由で転送します。

**起動方法**

1. 「Codespaces: Rebuild Container（コンテナの再構築）」を実行してCodespaceを再構築し、Docker-in-Docker機能がインストールされるようにします。
2. `.env.example` を `.env` にコピーします。ブラウザのユーザー名とパスワードは、どちらもデフォルトで `1234` です。ポート3000はプライベートに保ち、`.env` ファイルはGitにコミットしないでください。
3. ワークスペースのターミナルで `web run` を実行します。Chromiumが起動し、Codespacesが転送されたブラウザポートを自動的に開きます。
4. `.env` に設定した認証情報を使ってサインインします。ブラウザが自動的に開かない場合は、Codespacesの「Ports」タブから転送された3000番ポートを開いてください。

Codespaceが起動するたびに、ブラウザは自動的に起動します。停止するには `docker compose down` を実行してください。ブラウザプロファイル（ログイン情報やクッキーを含む）は、Gitの追跡対象外である `browser-data/` フォルダに保存されるため、Dev Containerを再構築してもデータは保持されます。ブラウザコンテナ自体は再構築時に再作成されますが、保存されたプロファイルを使って自動起動します（コンテナIDは保持されません）。Chromiumのクラッシュ復旧プロンプトは無効化されており、Dockerがブラウザを安全に停止できるよう猶予時間が設けられています。

> **セキュリティ上の注意:** ブラウザプロファイルには機密情報が含まれるため、`browser-data/` は必ずGitから除外した状態を維持してください。Codespaceを削除したり新しいCodespaceを作成したりすると、このフォルダは保持されないため、削除前に必要に応じてバックアップを取ってください。なお、Webサイト側のセッション期限切れなどにより、再ログインが必要になる場合があります。

`web` コマンドはCodespace作成時にインストールされます。既存のCodespaceにこのコマンドを追加した場合は、一度 `Codespaces: Rebuild Container` を実行してください。

**ファイルの利用方法**
ブラウザ上で使用したいファイルは `browser-files/` 内に配置してください。これらのファイルは `/workspace` に読み取り専用でマウントされ、ブラウザのファイル選択画面から開くことができます。このフォルダ内のファイルもGitの追跡から除外されます。

**ネットワークとアクセス制御**
転送ポートはプライベートに設定されています。この環境ではDockerブリッジからの送信トラフィックが利用できないため、ChromiumはCodespaceのホストネットワークを使用します。これにより、ブラウザコンテナは `localhost` で待機しているサービスを含め、Codespace上のサービスへ広範にアクセス可能になります。

* ポートはプライベートのまま保持し、パスワードを保護してください。
* 使用しない時はサービスを停止してください。
* アクセス権限を持っているサイトおよびネットワークに対してのみ使用してください。外部へのアクセスは、Codespacesのネットワークルールおよび各サイトの利用規約に従います。

ブラウザのHTTPポート3000は、Codespacesによってプライベートに転送されます。

**別のCodespaceへのインストール方法**
このセットアップを別のCodespaceに導入するには、対象リポジトリのルートでターミナルを開き、以下を実行します。

```bash
curl -fsSL https://raw.githubusercontent.com/nifunifunifura-stack/chromium-on-codespaces/main/install.sh | bash

```

インストーラーによって、対象のDev ContainerにDocker-in-Dockerとプライベートポート転送が追加されます。指示に従ってCodespaceを再構築すると、Chromiumが自動的に起動するようになります。詳細は `codespaces-chromium/README.md` をご確認ください。
